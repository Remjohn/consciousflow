Lesson 05 · Layer 3 — Orchestration Network

The Factory Floor Tour

You’ve seen the mechanism in isolation. Now, zoom out. The Conscious Coaching Platform requires you to manage six radically different operational contexts. The fundamental mechanism of the decorator is identical in all six, but its meaning changes across boundaries.

The Chassis (FastAPI)
Concept: The Doorman / Routing Engine

The Chassis is exposed to the open internet. It receives millions of arbitrary data packets. In this domain, decorators serve as the HTTP routers and security checkpoints.

  • @app.post — Tells the structural framework where a request should go.
  • @require_admin — Instructs the framework to bounce unauthorized traffic.
@app.post("/v1/trigger") @verify_api_key async def trigger_coach_cycle(data: dict): # No HTTP or Auth logic here. return launch_cycle(data)
The QA Department (Pydantic)
Concept: Data Physics / Containment

The QA Department intercepts hallucinated garbage from LLMs. Here, decorators do not route traffic; they impose rigid physics onto strings and integers.

  • @field_validator — Imposes a boundary constraint on a specific field before the system accepts the object into reality.
class ModelOutput(BaseModel): confidence: float @field_validator('confidence') def limit(cls, v): if v > 1.0: raise ValueError() return v
The Machinist (DSPy)
Concept: Signature Wrapping / Prompt Translation

The Machinist deals with prompt compilation. Decorators in DSPy transparently convert normal Python functions into structured LLM logic calls, bridging Python execution with neural rendering.

  • @dspy.typed_predictor — Wraps raw signature strings to enforce structural outputs globally across a module.
@dspy.typed_predictor class GenerateHumor(dspy.Signature): context: str = dspy.InputField() joke: str = dspy.OutputField()
The Robot Arm (Pi OS Harness)
Concept: Process Isolation & Resource Limits

The Robot Arm executes wild agentic shell commands on the physical machine. Decorators here enforce terrifyingly strict hardware thresholds to prevent an agent from wiping the disk.

  • @timeout(10) — Aborts the function by force if it runs too long.
  • @jail_environment — Changes the execution container before the shell command fires.
@timeout(10) @jail_environment def run_agent_cmd(cmd: str): return subprocess.check_output(cmd)
The Memory Engine (Neo4j)
Concept: Fault Tolerance / Temporal Wrapping

Neo4j graphs occasionally deadlock during parallel writing. In Memory, decorators handle the dimension of time, automating retry logic without polluting the write script.

  • @retry(attempts=3) — If the function throws a TransientError, the decorator pauses execution and loops the function again silently.
@retry(Neo4jTransientError, attempts=3) def merge_relationship(a_id, b_id): driver.execute_write(tx_merge)
The Skill Compiler (JIT)
Concept: Compute State Caching / Memoization

Compiling complex skills takes heavy compute. We only want to compile it once per variant. A cache decorator intercepts the request, checks its internal ledger, and skips the function entirely if it has seen the inputs before.

  • @lru_cache — A caching boundary in standard Python. Avoids re-computation.
from functools import lru_cache @lru_cache(maxsize=128) def compile_ast_to_graph(ast_string): # Expensive operation return build_graph(ast_string)

Defect Scenarios — Logical Puzzles

As an Architect, you will rarely write decorators from scratch. Instead, you will be hunting systemic failures caused by subtle misunderstandings of how decorators operate. Solve the following defect reports.

Puzzle 1: The Hollow Guardian
The QA department is trying to guarantee that trigger_count generated by the LLM is always less than 5. A junior engineer writes this:
class Config(BaseModel): trigger_count: int @field_validator('trigger_count') def check_trigger(cls, v): if v > 5: print("Warning: Trigger count is too high!") return v
When the LLM outputs {"trigger_count": 999}, what actually happens to the system? Type the EXACT ONE WORD action the validator performs on the erroneous integer: REJECTS, FIXES, or ACCEPTS.
Puzzle 2: The Blocked Bypass
The Memory Engine has a strict deadlock retry decorator layered over the cache decorator.
@retry(attempts=3) @lru_cache() def get_heavy_query(id): ...
Decorators wrap bottom-up. Because @retry is stacked ON TOP of @lru_cache, if the cache has a hit (it remembers the data), does the retry decorator ever get executed? Type exactly YES or NO.
