The Router Edge

This is where client TCP connections are handled. FastAPI automatically routes the request and gives you the `websocket` object. Your job is to orchestrate the loop without dying.

ccp_backend/routers/audio.py Python 3.12
from fastapi import APIRouter, WebSocket, WebSocketDisconnect from services.agent import run_coaching_session router = APIRouter() @router.websocket("/ws/coach/{session_id}") async def websocket_endpoint(websocket: WebSocket, session_id: str): await websocket.accept() try: # Enter the indefinite bidirectional stream while True: data = await websocket.receive_text() response = await run_coaching_session(session_id, data) await websocket.send_text(response) except WebSocketDisconnect: clean_up_session(session_id)
Defect Prediction: The Clean-Up

Look at the very last line: clean_up_session(session_id). Assume `clean_up_session` is a database write operation that saves standard metrics to Neo4j, taking ~200ms.

Pipecat Harness Shell Escapes

Sometimes you must leave Python entirely. Audio processing via `ffmpeg` requires spawning a separate system process. You cannot let Python wait for the C++ binary.

ccp_backend/audio/pipecat.py Python 3.12
import asyncio async def convert_webm_to_wav(input_path: str, output_path: str): # Spawn a completely independent OS process process = await asyncio.create_subprocess_exec( 'ffmpeg', '-i', input_path, '-ar', '16000', output_path, stdout=asyncio.subprocess.PIPE, stderr=asyncio.subprocess.PIPE ) # We do not block here. The Eventloop yields completely. stdout, stderr = await process.communicate() if process.returncode != 0: raise Exception(f"ffmpeg failed: {stderr.decode()}")
Defect Prediction: Process Control

What would happen if the Architect used os.system("ffmpeg ...") instead of asyncio.create_subprocess_exec?

DSPy Async Abstractions

DSPy modules typically run synchronously. But when making 100 simultaneous LLM inferences against OpenAI, we must use the Async abstraction layer.

ccp_backend/intelligence/rag.py Python 3.12
import dspy import asyncio async def evaluate_candidates(questions: list[str]): module = dspy.AsyncPredict("question -> answer") # We create the coroutines, but do not await them yet tasks = [module(question=q) for q in questions] # We gather them to execute concurrently via the Event Loop results = await asyncio.gather(*tasks) return results
Defect Prediction: Gather vs Loop

If we replaced `asyncio.gather` with a standard `for` loop that awaits each task sequentially:

results = []
for t in tasks:
    results.append(await t)

Are we still starving the Event Loop?
