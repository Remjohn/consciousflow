### **4. PRODUCTION EDGE CASES**

Types act as immune systems. You must know what the antibodies look like when an infection occurs.

#### **Edge Case 1: Pydantic Silent Type Coercion**
**Code State:** `session_id: str`
**Incoming Value:** `404` (An Integer)
**Result:** Silent Passthrough. Pydantic dynamically *coerces* the integer `404` into the string `"404"`. 
**Why CCP Handles it this way:** The QA Department is pragmatic. Upcast conversions from ints to strings rarely corrupt meaning. Rather than terminating a coaching session because a client ID arrived as a number instead of a string, Pydantic silently patches the data type and allows operation.

#### **Edge Case 2: DSPy Retry Loop Ignition**
**Code State:** DSPy Signature expects `OutputField(desc="A list of 3 strings")`
**Incoming LLM Output:** Returns a dictionary mapping numbers to strings.
**Result:** DSPy traps the failure, prevents Pydantic from crashing the app, and automatically generates an error prompt *back* to the LLM (e.g., "You returned a mapping, but I strictly require an array of strings. Fix this.")
**Why CCP Handles it this way:** Large parameter LLMs are non-deterministic. Expecting perfection on inference 1 is un-sovereign architecture. Expecting typed errors and routing them back through automatic LLM self-correction loops guarantees stability.

#### **Edge Case 3: FastAPI 422 Ejection**
**Code State:** `async def ingest(intensity_score: int):`
**Incoming HTTP URL:** `/ingest?intensity_score=High`
**Result:** Raw 422 HTTP Response to the Client layer.
**Why CCP Handles it this way:** The Chassis never processes invalid materials. We never let `"High"` reach the Neo4j database or the DSPy layer. We stop the logic tree instantly at the ingress point. Better to drop an API call than corrupt a client's historical trauma graph.
