# Chapter Syllabus: Lesson 01 — Variables, Types & Type Hints

**Topic Overview:**
This lesson explores the atomic units of data within the Conscious Coaching Platform (CCP). We are not teaching variables as generic programming labels; we are teaching them as the foundational raw materials of the Factory, and Type Hints as the Quality Inspection Tags that prevent catastrophic data corruption before it reaches the Machinist (DSPy) or the Laser Cutter (LLM).

**Key CCP Subsystems Targeted:**
1. QA Department (Pydantic models)
2. The Chassis (FastAPI Route Contracts)
3. The Machinist (DSPy Signatures)

**Core Primitives to Cover:**
- `str`: Coaching scripts, User IDs, LLM raw text output
- `int`: Session counts, Trigger intensity scores, Retry limits
- `float`: CBCS alignment scores (0.0 to 1.0), Voice DNA weights
- `bool`: Active session flags, Onboarding completion status
- Primitive Combinations: `list[str]`, `dict[str, float]`

**Architectural Rationale (Orchestration Dichotomy - Dictum 2):**
If no one specifies the type of a variable, the orchestrator becomes non-deterministic. Type constraints are the fundamental mechanism for maintaining sovereign control over agentic output.

**Layer 1 Goal:** Establish the absolute necessity of typing and variables as platform scaffolding.
**Layer 2 Goal:** Trace Pydantic, DSPy, and FastAPI typing in live architecture.
**Layer 3 Goal:** Observe typing across the 6 core systems.
**Layer 4 Goal:** Specify Pydantic and DSPy constraints under pressure.
