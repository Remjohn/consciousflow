Misconception: "Shifting changes the distribution"

Misconception: "Probabilities only approximately sum to 1"

02 — Temperature Scaling

Temperature divides logits before exponentiation. Its effect is exponential in 1/T — not linear.

Temperature-Scaled Softmax p_i(T) = exp(z_i / T) / Σⱼ exp(z_j / T) // Probability ratio between two tokens: p₁/p₂ = exp((z₁ − z₂)/T)

Halving T (from 1.0 to 0.5) does not double the ratio — it SQUARES the ratio: 3.00² ≈ 9.00. Temperature's effect is exponential in 1/T. This is why T=0.1 creates ratios of 485 million:1 from a mere 2-unit logit gap.

03 — Shannon Entropy: Computation

Entropy measures the expected surprise of a distribution. It is the single number that summarizes how uncertain the model is at any token position.

Shannon Entropy H(p) = −Σᵢ pᵢ log(pᵢ) // surprise of event i = −log(pᵢ); entropy = weighted average surprise

Bounds: 0 ≤ H(p) ≤ log(n) where n = vocabulary size. For one-hot: H = 0. For uniform over n: H = log(n).

Use: ln(0.7) ≈ −0.357, ln(0.2) ≈ −1.609, ln(0.1) ≈ −2.303

04 — Cross-Entropy, KL Divergence & Training Loss

The pre-training loss is cross-entropy. Understanding this decomposition reveals why KL divergence controls training behavior.

Key Decomposition H(p, q) = H(p) + KL(p ∥ q) // cross-entropy = entropy of true dist + divergence from true dist KL(p ∥ q) = Σᵢ pᵢ log(pᵢ / qᵢ) // always ≥ 0; equals 0 iff p = q (Gibbs' inequality)

When p is one-hot (training label): H(p,q) = −log q(y*). This is the negative log-likelihood — the standard SFT loss.

P
Prediction Gate — KL Divergence Direction

GRPO uses Reverse KL: KL(π_θ ∥ π_ref) as its penalty term. A different algorithm uses Forward KL: KL(π_ref ∥ π_θ).

Select which statement is TRUE for Reverse KL:

Misconception: "KL divergence is symmetric"

KL(p∥q) ≠ KL(q∥p) in general. Forward KL is mean-seeking — it penalizes q for missing any region where p has mass, forcing q to spread across all of p's modes. Reverse KL is mode-seeking — it penalizes q for having mass in regions where p has no mass, pushing q to concentrate on p's best modes. The asymmetry is the entire reason these two objectives produce different trained models.

Misconception: "Reverse KL forces coverage like Forward KL"

Read the formula: KL(π_θ ∥ π_ref) = Σ π_θ(y) log[π_θ(y)/π_ref(y)]. This is large when π_θ assigns probability to outcomes where π_ref assigns little. So the penalty pushes π_θ AWAY from regions where π_ref is small — it can safely ignore those regions entirely. The model is free to zero out low-quality outputs.

✓ Correct — Mode-seeking behavior confirmed

Reverse KL = KL(π_θ ∥ π_ref) is large when π_θ is high where π_ref is low. To minimize it, π_θ concentrates on π_ref's high-probability modes and ABANDONS low-probability modes. This is why GRPO produces focused, consistent coaching outputs — the trained model collapses toward the high-reward subspace of the reference distribution.

05 — The Production Sampling Pipeline

Every LLM token generation in production — including the CCP's Pipecat sessions — uses this exact pipeline. The order of operations is not arbitrary.

Standard Pipeline sample( top-p( softmax( z / T ), p ) ) // Step 1: divide logits by T → Step 2: softmax → Step 3: top-p filter → Step 4: sample
P
Prediction Gate — Pipeline Ordering

A developer accidentally applies top-p filtering BEFORE temperature scaling. Logits: z = [5.0, 1.0, 0.5]. T = 0.1. Top-p = 0.95.

What goes wrong?

Misconception: "Pipeline order doesn't matter if the same operations are applied"

At T=0.1, the scaled logits become [50, 10, 5]. Softmax of those: token 1 gets ≈1.0, all others ≈0. Top-p keeps 1 token. Now apply in wrong order: softmax of raw [5.0, 1.0, 0.5] → [0.982, 0.018, 0.000]. Top-p keeps token 1. Temperature then applied to 1 token = no effect. The two pipelines accidentally agree HERE — but at T=2.0 they diverge dramatically. The order defines the semantics of each operation.

✓ Correct — Order defines semantics

Temperature must scale the logits BEFORE softmax because temperature controls the SHAPE of the distribution entering top-p. At T=0.1, only the dominant token survives — top-p gets an already-peaked distribution. Applying top-p first means the filter sees a moderate distribution and keeps multiple tokens, then temperature concentrates among those. The nucleus composition changes fundamentally.

06 — Softmax Saturation & Attention Entropy

Softmax appears twice in Transformers: at the output (token selection) and inside attention (position weighting). Both can saturate. Saturation kills gradient flow.

Attention Softmax αₜ = softmax( qₜᵀKᵀ / √dₖ ) // √dₖ scaling prevents dot products from growing too large Saturation condition: when zᵢ ≫ zⱼ → softmax(z)ᵢ → 1, gradient → 0

The entropy of the attention distribution is a diagnostic for saturation:

  • H≈0Saturated. One token dominates. Gradients blocked. Attention frozen.
  • H≈logTUniform. All positions attend equally. No useful information routing.
  • 0.5–2.0Healthy range. Selective but not frozen. Gradients flow. Information routed effectively.
P
Prediction Gate — Saturation Diagnosis

An attention layer's entropy diagnostic shows H(αₜ) = 0.02 across all query positions after training epoch 3.

What does this indicate, and what caused it?

Misconception: "H→0 in attention means the model learned perfect routing"

H→0 in OUTPUT distributions (token selection) could be acceptable at inference with T→0. But H→0 in ATTENTION distributions means gradients have vanished: ∂pᵢ/∂zⱼ = pᵢ(δᵢⱼ − pⱼ). When pᵢ→1, the cross-gradient terms pᵢ·pⱼ→0. The attention layer is frozen. Whatever routing it has learned — good or bad — cannot be updated.

✓ Saturation correctly identified

H=0.02 is near-zero — the attention distribution is nearly one-hot. This is softmax saturation: large dot products push softmax into its tail where ∂p/∂z ≈ 0. The √dₖ scaling exists precisely to prevent this. Without it, as d_k grows, dot products scale as √d_k and saturate attention from the first forward pass. The entropy diagnostic catches this pathology quantitatively.
