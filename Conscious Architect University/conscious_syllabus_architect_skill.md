## 3. FIVE-TIER MODULE ARCHITECTURE

For every subsequent module (Module 1 through 16+), your outline must explicitly dictate ALL FIVE of the following tiers. Omitting any tier from any module is a structural failure.

### Tier 1: The Negative Space (What to Unlearn)
State the specific false belief, outdated paradigm, or cognitive trap the student must discard before they can absorb the lesson. This tier loads the contrastive architecture.
*   *Example:* "Unlearn the assumption that Docker containers and NIM containers are identical. NIMs encapsulate hardware-accelerated inference engines, not just software."

### Tier 2: First Principles & Systems Engineering
Define the indivisible atomic truth of the topic. Formulate how this truth fits into standard systems engineering frameworks (input/output boundaries, state machines, feedback loops, control theory), keeping the language clear and simple for beginners.

### Tier 3: The Core Concept & Pedagogical Association Directive
State the core lesson explicitly. Provide a *mandatory analogical directive* instructing the Module Instructor on which specific discipline(s) to use as the primary bridge for this module.
*   You must actively mandate analogies drawing from: **Neuroscience, Cognitive Architecture, Behavioral Change Psychology, Christianity/Theology, or Astrotheology Numerology**.
*   Be specific. Do not say "use a neuroscience analogy." Say: "Compare the Token Bucket rate-limiter to the neuron's Refractory Period—the absolute fraction of a second where a neuron cannot fire again, preventing epileptic runaway feedback."

### Tier 4: Python Codebase Teaching Mechanism
Natively integrate a fundamental Python concept mapped directly to the CCP architecture. You must specify:
*   The exact Python concept to teach (e.g., "dictionaries," "async/await," "context managers").
*   The exact CCP component to map it to (e.g., "the Telegram user state router," "the ComfyUI render queue").
*   The Python Difficulty Tier (1-4) from the Governance Protocol's progression curve. Early modules use Tier 1. Late modules use Tier 3-4.
*   **The Python Definition Rubric (MANDATORY):** Explicitly command the instructor to define the Python term fundamentally as if it were a dedicated coding sub-course. (e.g. "Command the instructor to explicitly define what a dictionary is before writing the code.")

### Tier 5: Falsifiable Learning Gate & PRD Reference
Define exactly what the student must be able to DO at the end of the module. This must be a binary, observable, testable outcome—not an abstract verb like "understand."
*   *Invalid:* "Understand how load balancing works."
*   *Valid:* "Write a Python function that iterates over a list of server loads and prints a CRITICAL alert if any value exceeds 80."
*   Explicitly list the exact filenames (e.g., `docs/prd/prd.md`, `Infrastructure_AWS_NIM_Deployment_Spec.md`) the module verifies against.

## 4. STRUCTURAL QUALITY GATES (SELF-VERIFICATION)

Before finalizing and outputting a syllabus, you must run this internal checklist. If any gate fails, revise before output.

- [ ] **Module Count Gate:** Does the syllabus contain Module 0 + exactly 16-18 learning modules?
- [ ] **Causal Chain Gate:** Does every module build strictly on the previous one? Could a student skip Module 6 and still understand Module 7? If yes, revise—the dependency is too loose.
- [ ] **Negative Space Gate:** Does every module explicitly state what false belief to unlearn?
- [ ] **Analogical Diversity Gate:** Are at least 3 out of 5 association disciplines (Neuroscience, Behavioral Psychology, Christianity, Astrotheology, Cognitive Architecture) represented across the full syllabus?
- [ ] **Python Progression Gate:** Do Python concepts escalate from Tier 1 (variables, strings) in early modules to Tier 3-4 (async, decorators) in late modules? Is there any Tier 4 concept deployed before its Tier 1-2 foundations are taught?
- [ ] **Ghost Variable Gate (M5):** Is every referenced document an actual, named file? Are there any vague references like "the architecture document"?
- [ ] **7-Reference Gate:** Does the `<SOURCE RESEARCH DIRECTORY>` explicitly list at least 7 exact paths to lab/docs files?
- [ ] **Falsifiable Gate (M6):** Is every learning objective a binary, testable outcome?
- [ ] **Centroid Repulsion Gate (M7):** Read the syllabus aloud. Does any module description sound like the Forbidden Centroid from the Governance Protocol? If yes, rewrite it.
